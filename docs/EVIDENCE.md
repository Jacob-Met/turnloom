# TURNLOOM execution evidence

## Observed local prototype

On October 27, 2026 the maintained manual-anchor application passed 13 automated tests and an actual four-context browser course on Node 22.23.4, Chrome 156.0.8078.47 and Playwright 1.64.1. The browser receipt records actual Chromium namespace, PID, network and seccomp sandbox admission. No page errors or external HTTP requests occurred; one intentionally aborted join response tested recovery.

The tests cover controller privacy and version bindings, exact owner-approved publication, terminal withdrawal with retained words, cross-participant refusal, saved state after restart, exact invitation replay, token-collision rejection without consuming another invitation, and a real storage-write failure returning a generic uncertain-outcome error. Package receiving built two identical archives, verified their complete file inventory and hashes, excluded saved rooms and development dependencies, extracted into a path containing spaces and an accented character, and ran the extracted server and assets. Existing artifact outputs were preserved and symlinked inputs refused.

The first browser course exercised actual invitation links, recovery after a discarded join response, four identities, private canaries absent from three peers, two real topic changes followed by return to the original point, an edit revoking readiness, explicit resharing as one new reservable anchor, unsaved words and caret surviving incoming updates, confirmed withdrawal retaining readable saved words, an actual shared export, 320/390/768/1280 layouts, and a same-data server restart. These are fictional software scenarios. Basic Tab movement in that first course was not proof of keyboard-only completion.

The subsequent course also passed: a deliberately injected startup 503 preserved the existing session key and the next poll reopened the correct participant; native Enter and Tab then reserved an anchor and saved an exact private draft. The expanded course records 13 named checks. This establishes that keyboard journey, not whole-application or switch-device accessibility.

## Response ordering receiving

A complementary October 27 browser course reproduced a stale-view defect against owner source `8bb17607b108ff46c57c1f68f0cc53b739a7df67`: an older background session response arrived after a newer draft save and replaced the visible composer with earlier words. The server still held the newer saved draft; the reproduced defect was in the browser view.

The repaired source passed eight focused actual Chrome cases: delayed reads after a save; delayed reads across participant entry; delayed successful commands across participant entry; serialized slow reads followed by a fresh update; a genuine server-generated stale-revision error across participant entry; unsaved words, focus, selection and ownership through both an old participant response and the next current-participant poll; and stalled-read timeout recovery for both the current and a newly accepted participant. The timeout cases keep the original response held until a later real poll renders a new server statement, and observe cancellation of the old browser read. These cases use authored fictional state and no live model calls. Command effects that already reached the server are not cancelled by view guards.

## Repeating and identifying the source

Run `npm test`, `npm run check` and `npm run package:runtime -- NEW_OUTPUT_DIRECTORY`. Run `node scripts/browser-course.mjs` and `node scripts/browser-refresh-course.mjs` with the documented development-only Playwright installation and `TURNLOOM_RECEIPTS` destination. `TURNLOOM_RUNTIME_ROOT` selects an extracted runtime for receiving; it does not change the source under test.

An archive's `runtime-manifest.json` records the exact source commit, whether inputs were modified, and every delivered file's hash. The adjacent checksum identifies the archive. Keep the external receiving receipt with that checksum; neither an embedded self-referential commit nor a fabricated artifact hash belongs in this note. Private repository publication and final clean-source receiving are separate from the initial working-tree results.

## Limits

This is a local-computer application, not a hosted multi-device deployment. Separate participant capabilities do not hide data from the host operator. The demo creator initially holds all four invitations. Withdrawal closes sharing while retaining saved private words.

No AAC co-design study, switch-device receiving, speech recognition, live NVIDIA/Nebius inference, AWS execution, public release or competition submission is established. The model projection is tested as local controller behavior; no live model request is available through this prototype's API. Automated completion does not demonstrate reduced interruption, improved topic reach, or reduced pressure. Those questions require appropriate participant evaluation.
